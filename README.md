# termbridge — мост «веб-чат ИИ ⇄ терминал»

Обычный ИИ-чат в браузере (ChatGPT, Claude, Gemini, любой другой) умеет только
текст. **termbridge даёт ему терминал:**

```
 ┌──────────────────────┐        ┌────────────────────────┐
 │  Браузер + чат ИИ    │  читает │      termbridge        │
 │  (вы залогинены)     │ ◄─────── ответы с блоком         │
 │                      │ ───────► [EXECUTE], выполняет    │
 │  ИИ пишет команду    │  шлёт   команду в bash/PowerShell│
 │  в блоке [EXECUTE]   │ ◄─────── и сам вставляет вывод    │
 └──────────────────────┘  вывод  обратно в поле чата      └───────┐
                                                                    │
                                                            ┌───────▼────────┐
                                                            │  терминал (PTY) │
                                                            └────────────────┘
```

ИИ не знает, что у него «нет рук»: вы один раз отправляете ему системный промпт
(`prompts/system_prompt.md`), где сказано, что он агент с доступом к терминалу.
Дальше он выдаёт команды в блоке:

````markdown
```bash
# [EXECUTE]
cd my_project && npm init -y
```
````

Мост видит такой блок, выполняет команду в **постоянной** shell-сессии
(`cd`, `export`, `source .venv/bin/activate` живут между шагами) и сам отправляет
вывод терминала следующим сообщением в чат. ИИ анализирует вывод, чинит ошибки
новой командой и идёт к результату — как opencode/Cursor, но через любой
веб-чат.

## Поддерживаемые чаты

| Чат | Распознавание | Поле ввода / отправка |
|---|---|---|
| ChatGPT (chatgpt.com) | встроенный адаптер | contenteditable + кнопка/Enter |
| Claude (claude.ai) | встроенный адаптер | contenteditable + кнопка/Enter |
| Gemini (gemini.google.com) | встроенный адаптер | contenteditable + кнопка/Enter |
| Любой другой сайт | **generic**-адаптер по CSS-селекторам в `config.yaml` | textarea/contenteditable |

Селекторы вендоров иногда меняются — если адаптер «ослеп», поправьте его в
`termbridge/adapters.py` (там списки селекторов через запятую) или используйте
generic.

## Установка

Нужен Python 3.10+ и установленный Chrome / Chromium / Edge.

```bash
git clone <этот репозиторий>
cd mod-minecraft

python3 -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

> Playwright ставится как библиотека управления **вашим** браузером по CDP —
> отдельный браузер качать не нужно.

## Запуск — 4 шага

### 1. Открыть браузер с портом отладки

```bash
python -m termbridge launch --site chatgpt     # или claude / gemini
```

Команда запустит Chrome с `--remote-debugging-port=9222` и отдельным профилем
(`.chrome-profile/`). Войдите в свой аккаунт ИИ в этом окне — вход сохранится
между запусками.

Если браузер не нашёлся автоматически — пропишите путь в `config.yaml`
(`browser.path`) или запустите вручную:

```bash
# Linux/macOS
google-chrome --remote-debugging-port=9222 --user-data-dir=./.chrome-profile
# Windows (PowerShell)
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --remote-debugging-port=9222 --user-data-dir="$PWD\.chrome-profile"
```

### 2. Проверить всё ли на месте

```bash
python -m termbridge doctor
```

Покажет статус шелла, CDP-подключения и найденные селекторы чата.

### 3. Отправить ИИ системный промпт

```bash
python -m termbridge prompt            # ОС подставится автоматически
python -m termbridge prompt --save prompt.txt
```

Скопируйте вывод и отправьте **первым сообщением** в чат. Текст промпта лежит
в `prompts/system_prompt.md` — его можно дополнять под себя.

### 4. Запустить мост

```bash
cp config.example.yaml config.yaml     # при желании подправить настройки
python -m termbridge run
```

Всё. Теперь пишите ИИ задачу («создай клон змейки на Python и запусти тесты»,
«разверни этот проект локально» и т.п.) — он будет выдавать блоки `[EXECUTE]`,
мост будет их выполнять и возвращать вывод.

## Управление во время работы

В терминале, где запущен `run`, работают команды:

| Клавиша | Действие |
|---|---|
| `p` | пауза (команды не выполняются) |
| `r` | продолжить |
| `s` | сбросить ожидающий ответа блок |
| `q` | выход |

Если включить в конфиге `require_confirmation: true`, мост будет спрашивать
`y/N` перед каждой командой.

## Конфигурация (`config.yaml`)

Ключевые опции (полностью — в `config.example.yaml`):

* `site` — `auto` / `chatgpt` / `claude` / `gemini` / `generic`;
* `tab_url_regex` — какую вкладку считать чатом, если открыто несколько;
* `shell.cwd` — рабочая папка терминала;
* `shell.command_timeout` — таймаут команды, потом шлётся Ctrl+C (по умолч. 600 с);
* `output.max_chars` / `head_chars` — обрезка длинного вывода (начало + конец);
* `process_existing_on_start` — выполнять ли команды из ответов, уже висевших
  в чате до старта моста (по умолчанию нет);
* `generic.*` — CSS-селекторы для произвольного сайта:
  `assistant_selector`, `composer_selector`, `submit: enter | button:<селектор>`.

Пример generic-конфига для собственного веб-интерфейса:

```yaml
site: generic
generic:
  assistant_selector: ".message.assistant"
  composer_selector: "textarea#prompt"
  submit: "enter"
```

## Как это устроено внутри

* `termbridge/browser.py` — подключение к запущенному браузеру по CDP
  (Chrome DevTools Protocol), поиск вкладки, ввод текста через «пасту» и отправка;
* `termbridge/adapters.py` — селекторы чатов;
* `termbridge/parser.py` — извлечение блоков `# [EXECUTE]` из markdown ИИ
  (терпит мелкие отклонения формата);
* `termbridge/executor.py` — постоянная PTY-сессия bash (Linux/macOS) или
  PowerShell (Windows), маркеры завершения, код возврата, таймаут + Ctrl+C;
* `termbridge/app.py` — цикл опроса страницы: новые ответы ждут «стабилизации»
  (ИИ перестал печатать), затем команда выполняется, а вывод уходит в чат;
* `termbridge/launcher.py` — запуск браузера с CDP и выделенным профилем.

## Безопасность — прочитайте

Мост выполняет команды, которые придумал ИИ, **на вашей машине, с вашими
правами, без песочницы**. Это и есть фишка, но и риск: модель может ошибиться
и выполнить деструктивную команду (`rm -rf`, форс-пуши, удаление БД и т.п.).

Рекомендации:

1. Сначала работайте с `require_confirmation: true`, пока не доверяете потоку.
2. Держите проекты в отдельной папке и указывайте её в `shell.cwd`; ещё лучше —
   в контейнере/VM.
3. Промпт требует флаги авто-согласия (`-y`, `-f`), поэтому команды не висят на
   запросе подтверждения, но и не остановятся перед удалением — вы предупреждены.
4. История всех выполненных команд печатается в терминале моста.
5. Не запускайте `run` на компьютерах с production-доступами без изоляции.

## Разработка

```bash
pip install pytest
python -m pytest tests/ -q
```

* `tests/test_parser.py` — разбор блоков `[EXECUTE]`;
* `tests/test_executor.py` — PTY-сессия: коды возврата, `cd`/`export` между
  командами, таймаут и Ctrl+C;
* `tests/test_e2e.py` — полный цикл на headless-Chromium и мок-странице чата
  (`tests/mock_chat/index.html`); как достать Chromium в офлайн-окружении —
  см. `tests/README.md`.

## Известные ограничения

* Нужен браузер на Chromium (Chrome/Edge/Chromium/Brave); Firefox не умеет CDP.
* Интерактивные программы (vim, top, `npm init` без `-y`, REPL) мост не
  обслуживает — промпт прямо запрещает их ИИ; зависшая команда прерывается по
  таймауту (Ctrl+C).
* Если сайт сменил вёрстку — поправьте селекторы адаптера или опишите сайт
  через generic; команда `doctor` показывает, что нашлось, а что нет.
* Автоматизация веб-чатов может нарушать правила конкретного сервиса — это ваш
  браузер и ваша ответственность.
